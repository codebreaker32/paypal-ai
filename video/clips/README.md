# Raw screen clips for the demo video

One MP4 per shot of [docs/DEMO.md](../../docs/DEMO.md), each **1920x1080 at a constant 30 fps** (H.264, yuv420p, no audio), recorded by `npm run clips`. They are raw material for a person to cut the final video (under 3:00): no narration, music, captions or speed-ups are applied. The MP4s are not committed (`.gitignore`); record them with the command below. Every clip shows the photo-first "Storefront" UI (white page, Figtree, black primary buttons, item photos; `docs/DESIGN.md`).

## What never reaches the screen

- **Sandbox logins** (`PAYPAL_SANDBOX_SELLER_EMAIL`, `PAYPAL_SANDBOX_BUYER_EMAIL`): every page and frame of the clip browser runs `scripts/clips/redact.browser.js` before the page's own scripts. It rewrites a login wherever it is drawn into the app's own masked form (`maskEmail`, `s•••@business.example.com`), and draws an input holding one as dots. On paypal.com it starts switched off (PayPal reads the login back from its own page, so masking it there fails the login) and is switched on after the login, before 06b; the recorder refuses to record 06b if a login is still visible. Chrome's password manager and autofill are off in the clip profile (its "Save password?" bubble shows the login in full and is out of a page script's reach).
- **The PayPal login itself:** not recorded (06 stops on the login page, 06b starts on the review page).
- **Owner links:** the seed's owner link is read by the recorder, used to log in, and never printed; on screen any `/claim/<token>` shows as `/claim/••••••••` (03's live screen holds the new shop's owner link).
- **Keys:** the terminal clips run with only the variables they need (05: `PATH`, `HOME`, `ANTHROPIC_API_KEY`; 07: `PATH`, `HOME`), and no command prints one.

## Recording

Needs Node 22, `npm ci`, Playwright's Chromium (`npx playwright install chromium`), and `Xvfb`, `ffmpeg` (with libx264), `xterm`, `jq` and Claude Code (`claude`) on the PATH (`sudo apt-get install -y xvfb ffmpeg xterm jq fonts-dejavu`). `.env` must hold the PayPal sandbox app keys, `ANTHROPIC_API_KEY`, `PAYPAL_SANDBOX_SELLER_EMAIL` (US sandbox Business: where the shops are paid) and `PAYPAL_SANDBOX_BUYER_EMAIL` / `PAYPAL_SANDBOX_BUYER_PASSWORD` (US sandbox Personal: the buyer). In a git worktree, give it a real `node_modules` (a hard-linked copy, `cp -al <repo>/node_modules node_modules`, is enough): with a symlink to one outside the worktree, `next build` (Turbopack) cannot find Next.js.

```bash
npm run clips                         # every clip, into video/clips/
npm run clips -- --only 03-,08        # re-record some (ids or prefixes; 03 replays 02's steps unrecorded)
npm run clips -- --only 03b           # only snap your counter (a prefix: --only 03 records 03 and 03b)
npm run clips -- --display :98        # another virtual display (default :97)
npm run clips -- --port 3253          # another port for the clip server (default 3251)
npm run clips -- --base-url http://localhost:3000   # an app you already run (see below)
npm run clips -- --build              # rebuild the app first (otherwise only when .next has no build)
```

Without `--base-url` it runs its own production server on port 3251 with its own database (`DATABASE_PATH=data/clips/clips.db`, `UPLOADS_DIR=data/clips/uploads`, `APP_URL=http://localhost:3251`; log in `data/clips/server.log`), runs `npm run seed` against it, logs in to the demo shop through the owner link the seed prints (kept as a cookie in `data/clips/owner-state.json`, gitignored; if it is lost the seed is re-run with `--reset`), re-seeds the demo shop with `--reset` before 05 (Claude Code tends to make up the same `client_request_id` for the same prompt, and the door would answer with an earlier take's order instead of placing one; this also logs in again with the new owner link and puts the bundled photos back), and runs `npm run seed -- --cancel-unpaid` before 06. A reset clears the paid order 08 and 09 use, so after `--only 05` record 06 again. With `--base-url`, start the shell with the same `DATABASE_PATH` (and `UPLOADS_DIR`) as that server so the seed reaches its database, and set `CLIPS_OWNER_LINK` to the demo shop's owner link unless a previous run's cookie works.

03b needs `ANTHROPIC_API_KEY` (the server's counter route calls Claude). It looks the two croissants up through the door's own `list_products`, removes their photos as the owner (not recorded), then records the Menu tab; it presses **Use** on every proposal for an item with no photo and leaves a **Replace** (an item that already has a photo) alone. It shares the live-reading rate limit (20 an hour per address) with 02.

Each shot runs in a fresh browser; the whole display is grabbed by ffmpeg's x11grab at 30 fps. Phone shots put a 390x844 frame (scaled to the display's height) on the app's grey (`--grey-100`); laptop shots lay pages out at 1440x810 CSS px (scale 4/3); the terminal is white with the app's ink. After each clip the recorder prints ffmpeg's frame counters; if it says *x11grab fell behind* (more than 2% repeated frames, usually a busy machine), re-record that clip with `--only`. 06 and 06b are always recorded together. 08 and 09 use the order 06 paid (saved in `data/clips/state.json`), so record 06 first; 09 restores 06's console conversation. Running it twice gives the same set of files (new orders and a new `marigold-bakehouse-N` shop each time).

`CLIPS_CHECK_LOGIN=1 npm run clips -- --only 06` stops after the PayPal login and saves a grab of the whole display to `/tmp/shelfie-clips-after-login.png`, to check that no browser bubble shows the login before recording 06b. `CLIPS_OUT=/tmp/clips-trial npm run clips` writes the clips somewhere else (a trial run that leaves `video/clips/` alone; it still uses and resets the clip database).

A clip is moved into place only when its shot worked, so a failed take keeps the previous file. The live capture encodes with x264's fastest preset into a temporary MKV and is re-encoded into the MP4 after each shot, which keeps x11grab at 30 fps on a busy machine; Chromium runs under `nice` for the same reason.
