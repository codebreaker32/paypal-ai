## S3: older Activity collapse

Built: `collapsedActivityKeys` in `src/components/shop/console-state.ts` (pure, tests in `tests/shop/console-ui.test.ts`), `ActivityPanel` gains `collapsed`, and `BuyerConsole` passes it. Two new specs in `e2e/shop.spec.ts`.

Choices the brief leaves open:

- **A step with one failed call stays open whole.** The rule works per Activity entry, so the failed call keeps its neighbours beside it.
- **A call still `running` when a newer turn starts stays open too.** That only happens when a turn failed mid-call, so it is an interrupted call that has not been relabelled yet.
- **The latest turn renders as before (no disclosure).** Only a collapsed entry is a `<details>`, so a failed call can never be folded by hand either.
- **`ms` moved for every row, in every turn:** it is now `Took N ms` at the top of a row's expansion.
- **The heading is one run of text** (`Activity · 3 calls to the agent door`). It was two flex items with no space between them, so its text read `Activity· 3 calls`.

Edited existing tests:

- `e2e/flow.spec.ts`: the Activity read changes from `allInnerTexts` to `allTextContents`, because the rows of an earlier turn are now folded and `list_products` is usually in an earlier turn. Both assertions on it are unchanged. Not run here: that spec needs live Claude and PayPal.

For the coordinator: demo clip `06-console-order` was recorded before this change. A re-record would show the first Activity card fold when the second message is sent.

## S4: receipt as a single column

`Receipt.tsx` is now one `max-w-measure` column at every width: the state with its actions, then the summary. The grey panel stays: on a white page with nothing else on a surface it reads as the one well, and no card sits in or beside it.

Choices the brief leaves open:

- **The column is centred on the page**, with its text left-aligned, like the auth screens. Left-aligned under the logo it would leave about 700 px empty on its right at 1440. The header and footer stay on the `page` width.
- **The title gained `overflow-wrap: anywhere`,** so a long shop name with no break cannot push past the narrower column.
- **Very long pickup notes can still push the action down.** On a paid pickup the paragraph is the seller's own pickup note, and it is not clamped because it is what the buyer came for. The specs cover the fixture copy only.

Tests: no existing test edited. Three added to `e2e/shop.spec.ts`: one column at 390 and 1440 px (summary under the action, same left edge, at most 36rem), and the primary action on the first screen at 390x844 and 360x640 (waiting and paid).

For the coordinator: demo clips 06 and 06b show the receipt, and they were recorded with the old two-column layout at 1920x1080. A re-record would show the single column.

## S5: setup review on a phone

Built as the brief says: `Actions` gets the `[1fr_1fr_auto]` grid under 640 px and `Remove` is an icon there (its word stays for screen readers); `ExampleCaption` gains `quiet` in Ready and Ask-in-person rows; one line above `Ready for PayPal`, shown only while an example shows in those lists.

One addition to the brief, because its grid does not fit every label on a phone: **a label too long for its track wraps inside its button** (the bin never does). Rows with no bin wrap at any width under 640 px; rows with the bin wrap only under 360 px, so `Looks right` stays on one line at 360 and 390. On a two-button row the second button also takes the empty third track, so there is no hole on the right. See Review round 2.

Choices the brief leaves open:

- **The corner mark did not exist.** The only corner badge was the add-photo icon, which drawings also carry, so the sentence would have been false. `ItemPhotoPicker` gains `markExample`: the word `Example` as a dark tag flush in the thumbnail's top-left corner (the owner asked that the seller can see which rows are examples). It takes no pointer, so a tap still opens the picker, and it is `aria-hidden`, because the quiet caption says it to screen readers.
- **Flagged cards get the mark too and keep their visible caption** (they are cards, not list rows), so the sentence is true of the whole screen. The Menu tab is unchanged.
- **The line counts Ready and Ask-in-person rows**, both of which went quiet. A flagged card alone does not bring it up.

Checked in a browser at 390 px (screenshot, and the new spec): the mark is readable and sits inside the thumbnail, the three buttons share a line, and the bin is at least 44 px wide.

Tests: no existing test edited. Added cases to `tests/components/example-photos.test.ts` and one spec to `e2e/setup-review.spec.ts`.

For the coordinator: at 320 px the logged-out public header (Dashboard, Log in, Add your shop) is 33 px wider than the page. It is not part of S5 and I left it alone. The review screen itself fits.
