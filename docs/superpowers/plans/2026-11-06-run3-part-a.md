# Run 3 Part A: image-first and lively — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every text stand-in for a picture with a real image or a Shelfie-drawn category illustration, make the product feel lively with purposeful motion, adopt shadcn/ui as the component base, and fix the coordinator's four layout and colour issues, without losing a feature or a test.

**Architecture:** A foundation branch lands first (shadcn base under the existing primitive APIs, the `motion` library behind a small set of motion primitives, colour-role tokens). An images branch runs beside it (Claude picks an item category during the menu reading, a bundled SVG illustration set, a shop-avatar fallback chain with a new logo upload). Two surface branches then apply motion and the layout fixes to the buyer screens and the seller screens.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind v4 (closed palette), shadcn/ui (copied components, `components.json`), `motion` (`motion/react`, `LazyMotion` + `domAnimation`), Vitest, Playwright, `@anthropic-ai/sdk` structured output (`claude-sonnet-5-5`).

**Spec:** the run brief's Part A (human decisions of 6 Nov, recorded in `docs/DECISIONS.md` "Run 3"), `docs/DESIGN.md`, `docs/JUDGING.md` Part C (amended 6 Nov: no initials, emoji or text tiles standing in for images).

## Global Constraints

- No initials, monograms, emoji or text tiles standing in for a picture anywhere. `monogram()` is deleted.
- Never show a stock photo of someone else's product as the seller's. Illustrations are never sent to agents as a product image (`image_url` in `list_products`, `image` in JSON-LD stay real photos only).
- Keep the Storefront direction, Figtree, the logo and the pomegranate accent `#c21a4b`. This is a liveliness pass, not a new direction.
- The brand accent never signals an error or a negative state. Errors use their own semantic red, clearly different in hue from pomegranate.
- All motion respects `prefers-reduced-motion` (`MotionConfig reducedMotion="user"` plus CSS). Animate only `transform` and `opacity` (no layout jank, no CLS). Durations come from the motion tokens (90/140/220/360 ms).
- Lighthouse performance ≥ 90 on `/s/marigold-bakehouse` (mobile preset, production build).
- No Skiper UI source is vendored (its free tier has no clear licence; DECISIONS). Ideas only, written from scratch, credited in `docs/ASSETS.md`.
- Keep every feature and every test; update selectors, never delete a test to make it pass.
- No raw colour values in components: add tokens in `src/app/globals.css` and `docs/DESIGN.md` first.
- No file pair that differs only by case (`Button.tsx` and `button.tsx`): the repo must clone on macOS.
- 44 px touch targets, no horizontal scroll at 390 px, axe 0 violations.

## Review Focus

- A shop with no logo, no cover and no menu photo (seeded or a draft): the avatar must still be an image (an illustration), never letters. Test in Task 2.
- An item whose category Claude left out or an old row with `category = NULL` (recorded samples, seeded demo shop, databases from runs 1–2): it gets a keyword guess, never a crash or an empty tile. Test in Task 2.
- A user with `prefers-reduced-motion: reduce`: no movement, final values (totals, statuses) shown at once. e2e in Task 3 and Task 4.
- The dashboard's first load: existing paid orders must not toast; only an order that turns paid after load does. Test in Task 4.
- Jumping to a menu section on a phone: the section heading lands below the sticky header and above the sticky "Order with an assistant" bar, not under either. e2e in Task 3.

- `Pressable({ as?, lift? = true, children, className, ...rest })` — hover lift (−2 px, shadow-md) and press scale 0.98 for cards and rows.
- `CountUp({ cents: number, format?: (cents) => string, className })` — animates from the previous value to the new one (360 ms); renders the final value in an `aria-live="off"` span with the final text as its accessible text; reduced motion shows the final value at once.
- `StatusSwap({ value: string, children, className })` — `AnimatePresence mode="popLayout"` crossfade with a 4 px rise when `value` changes.
- Tokens: `--color-error` / `--color-error-soft` (new semantic red; `danger` becomes an alias of it) and `--color-note` / `--color-note-soft` / `--color-note-ink` for helpful notes (AI brief, allergy notes), each with a computed AA contrast row in DESIGN.md.
