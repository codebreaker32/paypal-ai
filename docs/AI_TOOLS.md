# AI tools and models used in Shelfie

Every AI call in the running app goes to **Anthropic Claude** (`claude-sonnet-5-5`, set in `src/lib/ai/anthropic.ts`) through the official `@anthropic-ai/sdk`. The **PayPal Agent Toolkit** gives Claude real PayPal tools on the seller side. The **Model Context Protocol (MCP)** is how outside AI assistants reach a shop, and how the in-app assistant does too.

## In the product

| # | Where | Model / tool | What it does | How it is called |
|---|---|---|---|---|
| 1 | Menu reader, `src/lib/ai/extract.ts` (prompts in `prompts.ts`, schema in `schemas.ts`) | `claude-sonnet-5-5`, vision | Reads 1 to 4 photos of a handwritten, chalkboard or printed price list. Returns items with section, description, prices per size, the exact text read, a confidence level and notes for anything unclear (crossed-out prices, "2 for $7", "market price", blur). It also reports skipped lines (hours, address, add-ons) and photo problems so the app can give a specific retake tip. | `client.messages.parse` with structured output (`output_config.format` from a zod schema via `zodOutputFormat`), `effort: 'medium'`, `max_tokens` 16000. One retry, with the validation error in the prompt, if the output does not parse. **Prompt injection:** the system prompt says text in the photo is data, never instructions; a line that reads like an instruction is returned with `looks_like_instruction: true` and the normaliser drops it (it also drops items whose text matches an instruction pattern). Without an `ANTHROPIC_API_KEY`, the three sample menus use a recorded real reading (`src/lib/ai/samples/`); your own photos need the key. |
| 2 | Normaliser, `src/lib/ai/normalize.ts` | none (deterministic code) | Turns the reading into draft products: integer cents, size variants, duplicate merging, and four review flags (`MISSING_PRICE`, `MARKET_PRICE`, `CHECK`, `DUPLICATE`) the seller resolves with one tap. The AI drafts; the seller decides. | Pure function, unit-tested. |
| 3 | Order brief agent, `src/lib/ai/brief.ts` | `claude-sonnet-5-5` + PayPal Agent Toolkit | When an order is paid, an agent reads PayPal's own record of the order with the toolkit's `get_order` (and `get_shipment_tracking` if it looks shipped) and writes the seller a short brief: what to prepare, the buyer's requests, warnings. It reads only; its one write is `submit_brief`, a local tool with a strict JSON schema that saves the brief. If there is no key, the run fails or the agent never calls `submit_brief`, Shelfie stores a labelled template brief instead (`src/lib/ai/template.ts`). | Beta `client.beta.messages.toolRunner`, `effort: 'low'`, `max_iterations: 4` (`BRIEF_MAX_ITERATIONS`), with a run timeout. The toolkit tools reach Claude through `toolkit.asClaudeTools(['get_order', 'get_shipment_tracking'])`, and every call passes the ownership check `scopeTool` in `src/lib/paypal/toolkit.ts`, so a shop's agent can only read that shop's orders. |
| 4 | Tracking, `src/lib/paypal/toolkit.ts` | PayPal Agent Toolkit | Adds the seller's carrier and tracking number to the PayPal transaction (`create_shipment_tracking`). The buyer's agent reads it back through the agent door's `get_order_status`. | The toolkit tool, run directly by Shelfie code (not chosen by a model). |
| 5 | The agent door, `src/lib/mcp/` (`server.ts`, `tools.ts`, `instructions.ts`), route `POST /s/[slug]/mcp` | MCP server (`@modelcontextprotocol/sdk`, Streamable HTTP) | Gives every shop an endpoint any MCP client can use: `get_shop_info`, `list_products`, `create_order`, `get_order_status`. Prices come only from the shop; payment always needs the human to approve on PayPal. | Stateless: a fresh `McpServer` per request. Strict zod input schemas (unknown arguments such as `price` are rejected), structured outputs, error codes with hints, a rate limit on `create_order` (30 per hour per client IP), fixed server instructions that carry no seller text except the sanitised shop name. |
| 6 | In-app buyer console, `src/lib/agent/buyer-console.ts`, route `/api/assistant/[slug]` | `claude-sonnet-5-5` + MCP client | Lets anyone try ordering without their own AI setup. It connects to the shop's MCP endpoint over real HTTP (`StreamableHTTPClientTransport`), exactly like an outside agent, and the Activity panel shows each tool call. | Beta `toolRunner`, `effort: 'low'`, `max_iterations: 8` (`MAX_ITERATIONS`), at most 16 user turns per conversation (`MAX_USER_TURNS`), per-IP rate limit, prompt-cache breakpoints. The shop's MCP tools are wrapped as Claude tools that call the MCP client. The `create_order` idempotency key is derived from the session id plus the model's key, so retries within a conversation do not create a second order. |

### Why these choices
- **Structured outputs** mean the menu reading parses or fails loudly, so the review screen never renders malformed AI output.
- **Agents only where a model should choose the calls.** The brief agent decides which PayPal records to read. The money path (create order, capture) is deterministic code with idempotency keys.
- **The toolkit is never exposed to buying agents.** Its `create_order` takes the item price from the model. The agent door is the buyer-safe layer over PayPal. The toolkit is created with an allowlist of `orders.get`, `shipment.create` and `shipment.get` only.
- Per the project rules, requests never send `temperature`, a forced `tool_choice` or `thinking: disabled`.

## Used to build Shelfie (not shipped in the app)
- **Claude Code** (Claude Opus) planned, wrote and reviewed the code: brainstorming, spec, plan, then parallel implementation by subagents in git worktrees, with separate reviewer agents and an independent judge agent scoring each milestone against a fixed rubric (`docs/JUDGING.md`, `docs/judge/`).
- **Playwright** captures the screenshots the judge reviews. The sample menu photos in `public/samples/` were rendered from HTML sources in `public/samples/src/`, so no third-party images are used.
